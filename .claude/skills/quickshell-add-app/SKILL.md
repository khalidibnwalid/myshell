# Adding an app (Notepad is the model)

**Apps live in `apps/<App>/`, not in `modules/` or `services/`.** Those folders are for the shell itself (bar, panels, system services). One app = one folder holding everything of its own:

```
apps/Notepad/Notepad.qml   the window
apps/Notepad/Notes.qml     its service (singleton, found by bare name: same folder)
apps/Notepad/notepad.svg   its icon
apps/Notepad/open.sh       what the desktop entry runs
```

Shared things stay where they are: `components/`, `config/`, and `services/WindowManager.qml` (the `<app>Visible` flag). Inside `apps/<App>/` the imports are the same as in `modules/<Area>/` (`../../components`, `../../config`, `../../services/`). `shell.qml` imports `"apps/<App>"`. The install script and the launcher result point at `apps/<App>/<app>.svg`.

1. **Name things apart.** The window type and the service singleton must not share a name. Window `Notepad`, service `Notes`.
2. **Service** (`apps/<App>/<Thing>.qml`, singleton): holds the data and every change to it. Store under `$XDG_DATA_HOME/quickshell/<app>/` (small JSON file), not in the config folder.
   - Load with `Process` (`mkdir -p` then `cat`) and write with `FileView { preload: false; atomicWrites: true }`.
   - **Never write before the load finished** (`if (!loaded) return` in `save()`), and queue an action asked for before that (`createPending`, `openPending`). Otherwise a fast IPC call overwrites the saved data.
   - A file that fails to parse is copied to `<file>.corrupt`, never written over.
   - Edits in place (`obj.text = ...`) do not change a `property var`: call `xChanged()` and make bindings that read the object depend on the list (`Notes.notes;` as the first statement of the binding), or they stay stale.
   - Save typing with a restart `Timer` (about 600 ms), other actions at once.
   - **Files the user opens or saves**: the item remembers its `path`. Read with `Process` (`head -c` limit, path as an argument, never inside the shell string). Write by **stdin** (`stdinEnabled: true`, `onStarted: { write(text); stdinEnabled = false; }`), because a long text does not fit in one argument. Report with a short `status` that a `Timer` clears. File pickers are `QtQuick.Dialogs` `FileDialog` (open, and `FileDialog.SaveFile`); Ctrl+S saves to the remembered path or asks, Ctrl+Shift+S always asks, Ctrl+O opens.
3. **Window**: an `ApplicationWindow` whose visibility is `Apps.isOpen("<app>")` (see step 4), `onClosing` closes it, same `color:` expression as `Settings.qml` (`Config.appearance.settingsOpacity`), `title: "<App>"`.
   - Build it from existing components (`ListRow`, `IconButton`, `FieldInput`, `StyledText`, `Appearance.*`); see `quickshell-components`.
   - **Title bar**: the app's actions (open, save, copy, pin, delete…) are `IconButton`s in a header row at the top right, ending with the close button (`close` symbol) that clears `<app>Visible`. The footer only carries information (counts, status). Show the way back to a folded panel there too, as a visible button, not only a shortcut.
   - **Side list**: an `Item` that clips and animates `Layout.preferredWidth` (min/max bound to it; `Behavior` off while dragging) around a column of the dragged width. A `MouseArea` on its right edge resizes it (clamp 180-480); dragging below about 120 folds it away. Keep an even 12 px margin on every side, also when the panel is folded.
   - **Markdown**: a `View`/`Edit` `Segmented` in the title bar (and a shortcut). View is a `Text { textFormat: Text.MarkdownText }` in a `ScrollView` (`contentWidth: availableWidth`); it renders headings, lists, task boxes, tables, quotes, code and links. `Text.linkColor` has no effect on Markdown here (links stay dark blue). Do not use a read-only `TextArea` for the view: it swallowed the toggle shortcut. A focused `TextArea` also keeps `Ctrl+E` (end of line); use `Ctrl+Shift+V` for the mode switch.
   - **A note created with content** (opened from a file) must be built with that content (`create(text, path)`), not filled in afterwards: the editor loads when the note is selected and never notices later in-place changes (it also reloads on `notesChanged()` while unfocused).
   - A list the user can reorder: keep the order in the stored array itself (new items prepended), show rows by slot in a `Flickable` (`y: slot * (rowHeight + gap)`, `interactive: !dragging`) and drag them with a `DragHandler { target: null; xAxis.enabled: false }` on the row, which keeps the row's own click working. While dragging only a `list.order` array changes; save it once when the drag ends. Switch dragging off while a search filters the list. `components/SortableList` is for plain rows without click, selection or an `x`.
   - A list row that can be removed shows an `x` (`IconButton` over the row, `visible: row.hovered || x.hovered`, `trailingSpace` so the title keeps clear of it).
- **Keep the window file small** (see `apps/Audio/` and `apps/Notepad/`): the window (`<App>.qml`) holds the state, the computed lists, the functions and the wiring only. Each region of the screen is a file in `views/` (`Sidebar`, `TopBar`, `PlayerBar`, a list, a pane…) that takes what it shows as properties and reports what the user did as signals (`onSelected`, `onPlayRequested`): a view never reaches into the window by id. Small reusable pieces go in `components/`. The IPC target is `<App>Ipc.qml` and the in-window shortcuts are `<App>Keys.qml`, each an `Item` with a `window` property (an `IpcHandler` must not hold a `var` property: IPC rejects it, so the handler sits inside the `Item`). A view that has to be focused or cleared from the window exposes a function for it (`focusSearch()`). A view's root `Layout.*` properties travel with it, so the window only adds what is specific to its place.
4. **Manifest and loading** (`apps/<App>/app.json`, read by `services/Apps.qml`): `id`, `name`, `description`, `mode` (`inline`), `entry` (the window file), `icon` (the svg), `symbol` (Material fallback), `window` (`title`, `width`, `height`), `ipc` (the IPC target), `keywords` (the launcher finds the app by words that start with the typed text), `categories`, `desktopKeywords`, and `mime` + `open` (`open.sh`) when it opens files. Add one `import "apps/<App>"` line to `shell.qml`: Quickshell only lets the files of a folder see each other (siblings, singletons) when something imports the folder statically. Nothing else names the app: the loader in `shell.qml`, the launcher (`Search.qml`), the dock (`DockApps.windowId`), the icon and the desktop entry (`scripts/install-apps.py`) are all driven by the manifest. A service is created lazily, so call `refresh()` from the window when it opens.
   - **Window state** is `Apps`, not `WindowManager`: `visible: Apps.isOpen("<app>")`, `onClosing: Apps.close("<app>")`, `Apps.open/close/toggle("<app>")` everywhere else (also from other parts of the shell, such as a Quick Settings tile). An already open window is asked to come forward by `Apps.raiseRequested(id)`: `Connections { function onRaiseRequested(id) { if (id === "<app>") { root.raise(); root.requestActivate(); } } target: Apps }`.
   - **Switching off**: `Config.apps.disabled` lists the ids that are off. The loader does not load them and takes them away when they are switched off; give the window a `function shutdown()` that stops what runs without it (a timer that rings, a poll). Own processes and singletons are not stopped by unloading.
   - **A heavy app, or one that must outlive a shell reload** is `mode: "process"`: see `apps/Audio/`. A root file `<app>.qml` (so it can use `components/`, `config/`, `services/`) imports `apps/<App>` and holds the window; `scripts/ctl.sh` starts it (`qs -p <app>.qml`) when a command needs it and passes commands on; the shell loads only a small `entry` (shortcuts and the IPC target that call `ctl.sh`); the program quits by itself when the window is closed and nothing runs; the manifest gets `process`, `ctl`. The `quit` command must exist: switching the app off sends it.
   - **Process apps create the window on demand**: `<App>Program.qml` (always on: IPC, load, quit timer) + `LazyLoader` for `<App>.qml`; do not leave a hidden `ApplicationWindow` alive (see `quickshell-conventions`, Memory and weight). Put heavy engines in an external process (`mpv`) and helpers in Go under `helpers/`.
   - **Keyboard** (every app): build from the focusable components; add `ClickAway {}` as the last child of the window; give lists `activeFocusOnTab`, `ListNav` and a `FocusRing` on the current row; focus the main list when the window opens (`Qt.callLater`); Down from the search box focuses the list and Up on the first row returns; key hints in the status line and README. See `quickshell-ui-ux`, Keyboard.
5. **Ways to open it**: an `IpcHandler` (`target: "<app>"`, functions `toggle`, `open`, `close`, plus `openFile(path: string)` when it opens files; never `show`), a `GlobalShortcut { name: "<app>" }` (the user binds `global, quickshell:<app>`), and in-window `Shortcut`s. Opening over IPC does not give the window keyboard focus on this machine; do not call it a bug.
6. **Launcher, dock, icon and default app come from the manifest** (nothing to write): the svg is `apps/<App>/<app>.svg` (128 viewBox, `#1b2125` rounded tile, `#92cef5` shape, like `assets/settings.svg`); with `mime` the desktop entry runs `apps/<App>/open.sh %F` (`qs ipc call <app> openFile "$1"` when given a file, else `open`) and the app appears in Settings → Default apps. The shell's windows share one app id (`dev.noctalia.noctalia-qs`), so the dock tells them apart by the window title in the manifest. The running shell sees a new icon only after a restart (`qs kill; setsid -f qs`).
7. **Test the switch**: set `"disabled": ["<app>"]` in `config.json` for a moment: the IPC target, the desktop entry and the launcher result go, and a process app quits. Put it back.
8. **Window rule** (the user's `~/.config/hypr/config/windowrules.lua`, the one place besides the one `source` line we touch, and only because they asked): copy the Settings line with the new title (`float`, `size`, `center`), then `hyprctl reload`.
9. **README**: add a short section (what it is, where the data lives, IPC, bind line, shortcuts, the window rule, the file types it can open). Add any new command-line tool to the dependency list and `AboutPage.qml`'s `tools` map.
10. **Verify** (see `quickshell-verify`): reload log clean; `qs ipc call <app> open`; `hyprctl clients -j` shows the window floating at the rule's size; check the data file by content; `gio mime text/plain` lists the app; run `open.sh /some/file` and look at the result. Hot reloads (any file saved under the config folder, `.claude/` too) can leave a test window showing a stale frame; restart the shell (`qs kill; setsid -f qs`) before judging a screenshot. Typing tests: focus the window with `hyprctl dispatch "hl.dsp.focus({ window = \"address:0x...\" })"` (this Hyprland uses Lua dispatch syntax), confirm `hyprctl activewindow` is the app **before** every `wtype`, or the keys land in the user's terminal or editor (this happened once: Down keys went to VS Code). Focus and confirm again before each key, because the user's own focus changes under you; do not keep stealing their focus, stop and use the log when they are working. Also run `xdg-open <file>` for an app that opens files. Remove test data and debug hooks (`grep -c "TEMP debug"`), then report what was seen and what was not, and ask whether to commit.
